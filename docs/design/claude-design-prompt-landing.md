Нужно переделать визуальный стиль проекта «Радар оттока» и добавить лендинг. Прошлый вариант панели получился аккуратным, но слишком простым и типовым — такой стиль повторит любая команда. Нужен узнаваемый продукт с характером: продуманная анимация, интерактивные демонстрации, «вау» в первые пять секунд, но при этом читаемые цифры и спокойная работа с таблицами.

Сделай ДВА варианта лендинга (A и B) — с разным позиционированием и разным визуальным языком, чтобы мы выбрали. Структура блоков у них общая (ниже). Затем перенеси выбранный язык на экраны панели (раздел 6) — для обоих вариантов достаточно экрана «Обзор», остальные экраны сделаем после выбора.

# 1. Что за продукт

«Радар оттока» — аналитическая панель для маркетологов хостинг-провайдера. Клиенты платят за серверы по подписке (почасово, неделя, месяц, квартал, полгода, год). Панель каждый день отвечает на три вопроса: кому из клиентов нужно внимание, почему возник риск и сколько денег бизнес может потерять.

Как работает (это главный аргумент продукта — модель прозрачная, а не «чёрный ящик»):
- У каждого клиента score 0–100 = сумма баллов по признакам. Балл признака = вес × сила сигнала.
- Признаки: «Ждёт оплаты» (услуга удалится через 5 дней), «Скоро истекает без автопродления», «Не хватает средств на продление», «Неоплаченные счета», «Сервер выключен клиентом».
- Уровни: высокий (≥ 60), средний (30–59), низкий; особые — «Нет оценки» и «Ушёл».
- Деньги: ожидаемая потеря за 30 дней = выручка услуг за 30 дней × вероятность непродления. Пример из демо-данных: € 981,39 под угрозой, 16 клиентов высокого риска, 33 среднего из 200.
- Веса меняются в панели, рейтинг и деньги пересчитываются на глазах, без перезагрузки.
- Данные приходят в реальном времени; есть API, метрики для Prometheus, вход через SSO, запуск одной командой Docker Compose.

Главное действие на лендинге одно — кнопка «Войти в панель» (ведёт на /login). Второстепенная ссылка — «Документация API» (/api/v1/docs). Формы заявки нет.

# 2. Два варианта

## Вариант A — «Внутренний инструмент команды Aéza»
Позиционирование: инструмент, который хостинг сделал для своей команды маркетинга. Тон — инженерный, уверенный, «мы видим каждого клиента».
Визуальный язык «ночная консоль хостинга»:
- Тёмная графитовая основа #0B0D10, поверхности #13161B и #1A1E25, волосяные границы #262B33.
- Фирменный акцент — холодный голубой #38C5F0 (как полосы в бренде хостинга), используется для луча радара, активных элементов и ссылок; оттенок для свечения точек — тот же цвет с прозрачностью, свечение мягкое и только у точек радара.
- Цвета риска на тёмном: высокий #FF5A4E, средний #FFB547, низкий #3DD68C, нет оценки #6E7681.
- Текст #E8EBF0, вторичный #9AA3AF.
- Шрифты (с кириллицей): заголовки — Exo 2, 600–700, широкий технологичный; интерфейс — Golos Text; все цифры и ID — JetBrains Mono с табличными цифрами.
- Фактура: тонкая координатная сетка 24 px на фоне героя (2–3 % непрозрачности), концентрические кольца радара.

## Вариант B — «Продукт для любого хостинга»
Позиционирование: самостоятельный продукт, который любой хостинг или VPS-провайдер подключает к биллингу за день. Тон — деловой, про деньги: «вы теряете € каждый месяц и не знаете кому звонить».
Визуальный язык «финансовый отчёт с живыми данными»:
- Светлая тёплая основа #F4F1EC, карточки #FFFFFF, тёмные «врезки» #14161A для героя и финального блока.
- Акцент — глубокий кобальт #2B45D9; деньги под угрозой — карминный #C8322B; удержанные деньги — зелёный #1F7A4D.
- Шрифты: крупные заголовки и суммы — Unbounded 500–600 (широкий, характерный, с кириллицей); текст — Golos Text; цифры — JetBrains Mono.
- Фактура: крупная типографика сумм, тонкие линии-«графики» на фоне, плотные таблицы как в отчёте.

# 3. Структура лендинга (одинаковая для A и B, тексты под позиционирование)

Навигация: прилипающая шапка (логотип-словесный знак «Радар оттока», ссылки «Возможности», «Как считаем», «API», «Вопросы», кнопка «Войти в панель»). На телефоне — меню-шторка.

1. **Герой с живым радаром** (главная фишка, см. раздел 4.1). Слева заголовок и подзаголовок, кнопка «Войти в панель», ссылка «Документация API». Справа — радар.
   - A: «Мы видим, кто из клиентов не продлит сервер. За дни, а не после удаления». Подзаголовок: «Радар оттока каждую минуту пересчитывает риск по всей базе Aéza и показывает маркетологу, кому написать сегодня и сколько это стоит».
   - B: «Ваши клиенты уходят молча. Радар показывает кто, почему и сколько это стоит». Подзаголовок: «Подключите биллинг — и через минуту увидите сумму под угрозой на 30 дней и список клиентов, с которыми нужно связаться первыми».
2. **Проблема: «5 дней до удаления»** — история на прокрутке (раздел 4.2).
3. **Возможности** — 5 блоков, у каждого маленькая живая демонстрация (раздел 4.3): рейтинг с причинами; деньги под угрозой; настройка модели с предпросмотром; живое обновление; график «факт и прогноз».
4. **Как считаем** — интерактивная формула (раздел 4.4). Это блок для жюри: модель обоснована и объяснима.
5. **Чем отличаемся** — сравнение в виде таблицы из трёх колонок «Таблица в Excel / ML-модель / Радар оттока» по строкам: объясняет причину риска; считает деньги; меняется без программиста; работает без истории за годы; обновляется сам.
6. **Интеграции** — схема потока данных: «Биллинг → API снимка и событий → Радар → Панель маркетолога / Prometheus / SSO». Анимированная линия данных бежит по схеме (раздел 4.5). Подписи эндпоинтов моноширинным: PUT /api/v1/source/snapshot, GET /metrics.
7. **Надёжность** — 4 факта списком с иконками: вход по паролю или SSO; без входа данные недоступны; метрики для Prometheus; запуск одной командой docker compose up.
8. **Частые вопросы** — 6 вопросов-аккордеонов: «Почему не нейросеть?», «Откуда берутся данные?», «Что если данных по клиенту мало?», «Как добавить новый признак?», «Как часто обновляется?», «Можно ли поменять формулу?» (ответы короткие, по 1–2 предложения, по смыслу из раздела 1).
9. **Финальный блок** — крупная сумма «€ 981,39 под угрозой прямо сейчас» (в B — на тёмной врезке, в A — с радаром на фоне) и кнопка «Войти в панель».
Подвал — минимальный: название, «Документация API», год. Без соцсетей и выдуманных контактов.

# 4. Фишки и анимация (обязательно, это суть задания)

Общие правила движения: каждое движение что-то объясняет; длительности 200–600 мс для интерфейса, длинные циклы только у радара; easing — cubic-bezier(0.22, 1, 0.36, 1); анимируются transform и opacity; при prefers-reduced-motion все циклы останавливаются, показывается статичное состояние.

## 4.1 Живой радар в герое
- Круг из 4 концентрических колец: внешнее — низкий риск, ближе к центру — средний, центр — высокий. Клиенты — точки; радиус точки зависит от суммы под угрозой.
- Луч обходит круг за 6 секунд; точка, через которую прошёл луч, ярко вспыхивает и за 1,2 с гаснет до спокойного состояния — как на настоящем радаре. Точки высокого риска медленно «дышат» (масштаб 1 → 1,15, 2,4 с).
- Наведение или фокус на точке — карточка-подсказка: «user-0110@example.test · score 100 · € 47,30 · Ждёт оплаты, до удаления 24 ч».
- Каждые ~8 секунд происходит событие: одна красная точка плавно (900 мс) переезжает на внешнее зелёное кольцо, рядом короткая подпись «user-0088 пополнил счёт · риск 40 → 12», и сумма «€ … под угрозой» под радаром обновляется (без «набегающих» цифр — смена через короткий кросс-фейд 200 мс).
- На телефоне радар уменьшается и уходит под заголовок, событий меньше.

## 4.2 «5 дней до удаления» — история на прокрутке
Блок прилипает на ~250 % высоты экрана; прокрутка двигает сюжет:
- шкала дней «День 0 … День 5» заполняется;
- карточка услуги «web-0021 · 12 € / мес» меняет статус «Активна → Ждёт оплаты → Удалена», цвет метки меняется;
- полоса «Выручка клиента за год» тает справа налево;
- в конце — второй слой поверх: «С радаром: в день 0 маркетолог получил клиента в списке с причиной „Не хватает средств: на счёте € 4,66, нужно € 521,91“ и рекомендацией „Предложить пополнить счёт сегодня“». Полоса выручки возвращается.
На телефоне — та же история, но шаги переключаются свайпом/кнопками «Дальше», без прилипания.

## 4.3 Живые мини-демонстрации в «Возможностях»
- Рейтинг: таблица из 5 строк; каждые 4 с меняется сортировка (по score ↓, по балансу ↑), строки переезжают на новые места (FLIP, 450 мс).
- Деньги: сумма и разбивка «ожидаемо / худший случай»; полоса «покрыто балансом» заполняется при появлении блока.
- Настройка модели: ползунок сам двигается 20 → 35, рядом плашка предпросмотра «Высокий риск: 16 → 19 · +€ 64,20».
- Живое обновление: точка-индикатор и строка «пересчитано 0 с назад», счётчик секунд растёт, затем сбрасывается с коротким подсвечиванием изменившейся строки.
- График: столбцы «факт» (сплошные) слева от линии «сегодня», «прогноз» (штриховка) справа; при появлении блока столбцы вырастают слева направо с задержкой 30 мс друг за другом.
Мини-демо запускаются, только когда блок виден на экране.

## 4.4 Интерактивная формула
Три ползунка (веса признаков «Ждёт оплаты», «Не хватает средств», «Скоро истекает без автопродления») и таблица из 6 клиентов со score и уровнем. Пользователь двигает ползунок — score пересчитываются, строки пересортировываются с анимацией, метки уровней меняют цвет, внизу итог «Под угрозой € …». Под таблицей формула текстом: «score = Σ вес × сила сигнала, не больше 100». Это реальная интерактивность, не видео.

## 4.5 Поток данных в «Интеграциях»
По линиям схемы бегут маленькие «пакеты» (точки) от биллинга к радару и дальше к панели и Prometheus; на узле «Радар» при приходе пакета — короткая вспышка контура.

## 4.6 Мелочи, которые делают «приятно»
- Кнопка «Войти в панель»: при наведении стрелка уезжает вправо на 4 px, фон чуть светлеет; при нажатии — масштаб 0,98.
- Появление блоков: заголовок и контент проявляются по-разному (заголовок — прозрачность + сдвиг 12 px, контент — с задержкой 80 мс), а не одинаковой «выплывающей снизу» анимацией на всём.
- Активный пункт навигации подсвечивается при прокрутке до своего раздела.
- Курсор на радаре — перекрестие.

# 5. Запреты (иначе получится «как у всех»)
- Без градиентных пятен на фоне, glassmorphism, 3D-иллюстраций, стоковых фото людей, эмодзи.
- Без капсовых подписей-«бровей» над заголовками, без нумерации 01/02/03, без выделения одного слова в заголовке цветом или курсивом.
- Без бегущих строк, «набегающих» счётчиков, одинаковой fade-up-анимации на всех блоках.
- Без трёх одинаковых карточек-фич в ряд с иконками в кружках.
- Без выдуманных логотипов клиентов, отзывов, процентов «снизили отток на 60 %».
- Свечение (glow) — только у точек и луча радара в варианте A.

# 6. Панель в новом стиле
Перенеси язык каждого варианта на экран «Обзор» панели (структура та же, что в прошлом задании: строка статуса «Данные на … · пересчитано N с назад», главная сумма с пояснением и «Как считается →», распределение клиентов по уровням, график «Отток по дням» факт/прогноз, топ-5 клиентов). Добавь на «Обзор» компактный радар клиентов (тот же, что в герое, но со всеми клиентами и фильтром по уровню). Таблицы и формы остаются спокойными и читаемыми: анимация в панели — только функциональная (подсветка изменившейся строки 1,5 с, плавная смена чисел в предпросмотре, раскрытие панелей).

# 7. Адаптивность и доступность
- Макеты лендингов в 1440 px и 390 px; панель «Обзор» — 1440 px.
- Контраст текста не ниже WCAG AA на обоих фонах; уровни риска и факт/прогноз различимы без цвета (подписи, штриховка).
- Все интерактивные элементы доступны с клавиатуры, видимый фокус; у радара — текстовая альтернатива («16 клиентов высокого риска, 33 среднего, под угрозой € 981,39»).
- Области нажатия не меньше 44 × 44 px; без горизонтальной прокрутки страницы на телефоне.

# 8. Что передать
1. Два лендинга (A и B) в 1440 и 390 px с описанием всех анимаций: что, когда запускается, длительность, easing.
2. Экран «Обзор» панели в стиле A и в стиле B.
3. Токены каждого варианта в CSS-переменных (цвета, шрифты, размеры, отступы, радиусы, длительности).
4. Экспорт в HTML/CSS/JS, где радар, история на прокрутке и интерактивная формула работают в браузере (чистый JS или CSS, без тяжёлых библиотек), — разработчик перенесёт их в React.
