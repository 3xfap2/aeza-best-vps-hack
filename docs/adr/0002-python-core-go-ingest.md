# 0002. Ядро на Python, приём потока событий на Go

**Статус:** принято.

## Контекст
За три дня нужно было сделать модель, деньги, очередь удержания, API, вход, метрики и панель. Отдельно — принимать поток событий биллинга без задержек, даже когда пересчёт занят.

## Решение
- Модель, деньги и API — Python 3.12 + FastAPI (`api/`). Правила считаются в одном месте, Swagger и OpenAPI генерируются из кода.
- Приём потока — отдельный сервис на Go (`ingest/`): проверяет форму пачки до 10 000 событий, одной транзакцией кладёт её в очередь `event_inbox` в PostgreSQL и сразу отвечает 202. Повтор события с тем же `eventId` отбрасывается.
- API забирает очередь пачками по `LISTEN/NOTIFY` (`api/app/inbox.py`).

## Последствия
- Приём держит около 12 700 событий/с на ноутбуке (`tools/bench_ingest.py`), пересчёт не тормозит биллинг.
- Очередь переживает перезапуск API.
- Правила риска и денег не дублируются в двух языках — их нельзя случайно рассинхронизировать.
- Клиент API на Go или Rust генерируется из `docs/openapi.json`.

## Отброшено
- Всё на Go: за три дня — риск ошибиться в деньгах, а модель пришлось бы писать заново.
- Kafka или NATS: для этого объёма PostgreSQL-очередь проще в эксплуатации, а гарантии те же.
