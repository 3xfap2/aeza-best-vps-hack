# 0001. Балльная модель вместо машинного обучения

**Статус:** принято.

## Контекст
В данных кейса есть только текущее состояние: аккаунты, услуги, транзакции. Истории уходов нет — неизвестно, кто из клиентов в прошлом ушёл и почему. Кейс требует, чтобы маркетолог видел причину оценки и сам менял коэффициенты.

## Решение
Прозрачная сумма баллов (scorecard): `score услуги = min(100, Σ вес × сила сигнала)`, клиент — максимум по его действующим услугам. Каждый признак — отдельный класс в `api/app/scoring/features/`, вес и порог меняются в панели с предпросмотром. Вероятность непродления = score / 100 — договорённость для денежной оценки, а не обученная величина.

## Последствия
- Каждое число объяснимо: в карточке клиента видно, какой признак сколько баллов дал.
- Новый признак — один файл; он сам появляется в настройках, карточке, Swagger и метриках (тест `test_new_feature_is_picked_up_everywhere`).
- Точность модели мы не заявляем. Чтобы её проверять и калибровать, есть сверка с исходами ([0010](0010-backtest.md)).

## Отброшено
Градиентный бустинг или логистическая регрессия: обучать не на чем, а «модель» на выдуманной разметке была бы подгонкой.
