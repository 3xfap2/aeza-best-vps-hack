# 0006. Очередь удержания по сроку потери, а не по риску

**Статус:** принято.

## Контекст
Услуга, которая ждёт оплаты, удаляется через 5 дней вместе с данными, и такой клиент почти наверняка уходит. У менеджера ограниченное число звонков в день.

## Решение
Очередь сортируется по сроку, когда деньги будут потеряны безвозвратно, а внутри срока — по выгоде контакта: сохраним (реально собираемая потеря × доля удержания) − стоимость звонка. Звонок предлагается, только если он окупается, иначе хватит письма. Логика — `api/app/retention.py`.

## Проверка
`compare_strategies` моделирует неделю при одном и том же числе звонков в день: деньги клиента сохраняются, только если позвонили до срока. На демо-наборе при 10 звонках в день план сохраняет € 479, список «по сумме потери» — € 471, список «по score» — € 403 (и упускает € 79). При 3 звонках в день план сохраняет вдвое больше списка по score.

## Последствия
- Дорогой клиент со сроком через неделю может подождать до завтра; тот, кто удалится сегодня, — нет.
- Это сценарий на текущих данных: новые события за неделю он не учитывает. Это подписано на экране.
