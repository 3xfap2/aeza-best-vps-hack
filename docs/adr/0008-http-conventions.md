# 0008. HTTP-соглашения: problem+json, ETag, If-Match, Idempotency-Key

**Статус:** принято.

## Контекст
API используют панель, биллинг, Telegram-бот и внешние системы. Ошибки, конкурентные правки и повторы запросов должны обрабатываться одинаково и предсказуемо.

## Решение
По RFC 9110, 9457, 8288 и черновику IETF Idempotency-Key, в одном месте (`api/app/http.py`, `api/app/idempotency.py`, `api/app/observability.py`):
- ошибки — `application/problem+json` с `detail` по-русски и `requestId`;
- у GET-ответов есть `ETag`, повтор с `If-None-Match` — 304 без тела;
- настройки модели: `ETag` в GET → `If-Match` в PATCH, не совпал — 412;
- создание — 201 и `Location`;
- страницы — `Link` с закреплённой версией расчёта, пересчёт между страницами — 409;
- любой POST с `Idempotency-Key` безопасно повторять: повтор вернёт сохранённый ответ.

## Последствия
- Клиент на любом языке обрабатывает ошибки одной функцией.
- Сеть оборвалась после пополнения — повтор с тем же ключом не зачислит деньги дважды.
- Таблица соглашений — в README, раздел «API».
