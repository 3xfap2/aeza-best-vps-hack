# 0003. Результат расчёта — в памяти одного процесса

**Статус:** принято; пересмотреть, когда понадобится больше одного экземпляра API.

## Контекст
Панели нужен мгновенный ответ на любую сортировку и фильтр, а пересчёт должен быть атомарным: никто не должен видеть половину старых и половину новых оценок.

## Решение
Данные источника и настройки живут в PostgreSQL. Результат расчёта (`EngineResult`) держится в памяти процесса API и подменяется целиком после пересчёта (`api/app/state.py`). Изменения данных идут по одному под `write_lock`, у каждого результата есть номер версии. Клиенты в панели получают событие по SSE и перечитывают данные.

## Последствия
- Чтение — без запросов к базе, сортировка 100 000 клиентов — в памяти.
- Версия расчёта есть в ответах, по ней страницы списка закреплены за одними данными (409 при пересчёте между страницами).
- **Ограничение:** один экземпляр API. Второй посчитал бы своё, а SSE рассылает события только своим подписчикам.

## Как масштабировать дальше
1. Записывать результат пересчёта в таблицу с версией (read model) и читать оттуда.
2. Рассылать «пересчитано, версия N» через `LISTEN/NOTIFY` всем экземплярам.
3. Пересчёт выполнять одним экземпляром под advisory lock PostgreSQL.

До этого поток событий уже вынесен в отдельный сервис ([0002](0002-python-core-go-ingest.md)), а событие пересчитывает только затронутых клиентов ([0004](0004-partial-recalculation.md)).
